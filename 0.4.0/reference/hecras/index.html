    HEC-RAS 2D — plan HDF5#

    Reader for the HEC-RAS 2D plan format (task D11).

    A HEC-RAS plan file is an HDF5 tree holding one or more named 2D flow areas, each an unstructured mesh of polygonal cells, plus unsteady results. The mesh nodes are the FacePoints; each cell's polygon is reconstructed from its ordered faces (Cells Face and Orientation into Faces FacePoint Indexes). The per-cell maximum/minimum water-surface summary in the plan file becomes face-located variables.
    Driver name hecras
    Suffixes .hdf, .hdf5
    Capabilities read_mesh, read_data, lazy_data
    Extra required none
    Returns UgridDataset

    .hdf is shared with other HDF5 formats, so the sniff keys on the HEC-RAS group layout (Geometry/2D Flow Areas with a Faces FacePoint Indexes geometry), not the suffix.

    from pyramids.netcdf.ugrid import UgridDataset

mesh = UgridDataset.read_file("model.p01.hdf")
wse = mesh.get("Maximum Water Surface")   # face-located, per cell

    Documented limitations#

    • Only the first 2D flow area is read. A plan file may hold several; selecting a second 2D mesh by name is not wired through the read template yet, so the first area is read and the others are named in a warning rather than dropped silently.
    • Ghost/boundary cells are excluded. HEC-RAS appends perimeter cells (a single face each) after the real cells; Cell Info gives the real-cell count, and only those closed polygons become faces. The per-cell summary arrays, sized to include the ghost cells, are sliced to the real cells to match.
    • Summary results only. The plan file carries the maximum/minimum water-surface summary; the per-timestep series lives in a separate, geometry-stripped *.timeseries.hdf companion, which cannot be paired into a single read here.
    • Face velocities are not exposed — they are edge-located (one per face, not per cell); this reader builds the cell mesh only.
    • Values are lazy — the loader reopens the file per read, closing over a path.
    • There is no CRS in the arrays read here, so crs is None.

    HDF5 is read through the GDAL multidimensional API over the GDAL vendored in pyramids-gis (activated by import pyramids) — no declared dependency and no h5py.

    class HecRasDriver(BaseDriver):
    """Reader for the HEC-RAS 2D HDF5 plan format.

    A plan file holds one or more named 2D flow areas, each an unstructured mesh of
    polygonal cells, plus unsteady results. The mesh nodes are the ``FacePoints``; a cell's
    polygon is reconstructed from its ordered faces (``Cells Face and Orientation`` into
    ``Faces FacePoint Indexes``). The per-cell summary results (maximum/minimum water
    surface) in the plan file become face-located variables.

    Documented limitations:
        - **Only the first 2D flow area is read.** A plan file may hold several; selecting a
          second 2D mesh by name is not wired through the read template yet, so the first
          area is read and the others are named in a warning rather than dropped silently.
        - **Ghost/boundary cells are excluded.** HEC-RAS appends perimeter cells (a single
          face each) after the real cells; ``Cell Info`` gives the real-cell count, and only
          those closed polygons become faces. The per-cell result arrays, which are sized to
          include the ghost cells, are sliced to the real cells to match.
        - **Summary results only.** The plan file carries the maximum/minimum water-surface
          summary; the per-timestep series lives in a separate, geometry-stripped
          ``*.timeseries.hdf`` companion, which cannot be paired into a single read here.
        - **Face velocities are not exposed.** They are edge-located (one per face, not per
          cell); this reader builds the cell mesh only.
        - There is no CRS in the arrays read here, so ``crs`` is ``None``.

    Example:
        Read a HEC-RAS 2D plan file (shown, not run as a doctest -- it needs a real HDF5
        file)::

            from pyramids.netcdf.ugrid import UgridDataset

            mesh = UgridDataset.read_file("model.p01.hdf")
            wse = mesh.get("Maximum Water Surface")   # face-located, per cell
    """

    name = "hecras"
    long_name = "HEC-RAS 2D"
    suffixes = (".hdf", ".hdf5")
    api_version = MESH_DRIVER_API_VERSION
    capabilities = frozenset({"read_mesh", "read_data", "lazy_data"})

    def _sniff(self, path: str) -> bool:
        """Report whether the file is a HEC-RAS 2D plan: HDF5 plus a 2D flow-area mesh.

        The magic is checked cheaply first; then the file is opened to confirm a
        ``Geometry/2D Flow Areas`` group with at least one area carrying the defining
        ``Faces FacePoint Indexes`` geometry. ``.hdf`` is shared with other HDF5 formats, so
        the group layout -- not the suffix -- decides, and a results-only (geometry-stripped)
        companion is declined.

        Args:
            path: The file to inspect.

        Returns:
            bool: ``True`` when the magic matches and a 2D flow-area mesh is present.
        """
        with open(path, "rb") as handle:
            if handle.read(len(_HDF5_MAGIC)) != _HDF5_MAGIC:
                return False
        with gdal.ExceptionMgr(useExceptions=True):
            try:
                dataset = gdal.OpenEx(path, gdal.OF_MULTIDIM_RASTER | gdal.OF_READONLY)
            except RuntimeError:
                return False
            try:
                root = dataset.GetRootGroup()
                if _GEOMETRY not in root.GetGroupNames():
                    return False
                geometry = root.OpenGroup(_GEOMETRY)
                if _AREAS not in geometry.GetGroupNames():
                    return False
                areas = geometry.OpenGroup(_AREAS)
                return any(
                    _FACE_FP in areas.OpenGroup(name).GetMDArrayNames()
                    for name in areas.GetGroupNames()
                )
            finally:
                dataset.Close()

    def _parse(self, path: str, *, lazy: bool) -> ParsedMesh:
        """Read the first 2D flow area of a HEC-RAS plan file into a :class:`ParsedMesh`.

        Args:
            path: The HEC-RAS ``.hdf`` plan file.
            lazy: When ``True``, leave each summary variable behind a loader.

        Returns:
            ParsedMesh: The flow-area mesh and its summary water-surface variables.

        Raises:
            FileFormatNotSupportedError: If no readable 2D flow area is present.
        """
        return _HecRasReader(path, lazy=lazy).build()

    can_open(path) #

    Report whether this driver recognises the file, without ever raising.

    A missing path or a directory answers False, and so does a suffix this driver does not claim. Everything about the file's content is the subclass's _sniff to judge, and the default _sniff judges nothing -- so on BaseDriver itself an empty file with a claimed suffix answers True. A driver that means to decline an empty or foreign file reads a header signature, as :meth:~pyramids_mesh.drivers.sms.TwoDmDriver._sniff does.

    A _sniff that fails for any reason is reported as a warning and the file declined, so a broken candidate cannot abort driver dispatch. Only _sniff sits inside that guard: a TypeError from being handed something that is not a path is the caller's mistake, not a verdict about a file, so it propagates.

    Returns:

    Name Type Description
    bool bool

    def can_open(self, path: str) -> bool:
    """Report whether this driver recognises the file, without ever raising.

    A missing path or a directory answers ``False``, and so does a suffix this
    driver does not claim. Everything about the file's *content* is the subclass's
    ``_sniff`` to judge, and the default ``_sniff`` judges nothing -- so on
    ``BaseDriver`` itself an empty file with a claimed suffix answers ``True``. A
    driver that means to decline an empty or foreign file reads a header signature,
    as :meth:`~pyramids_mesh.drivers.sms.TwoDmDriver._sniff` does.

    A ``_sniff`` that fails for any reason is reported as a warning and the file
    declined, so a broken candidate cannot abort driver dispatch. Only ``_sniff``
    sits inside that guard: a ``TypeError`` from being handed something that is not
    a path is the caller's mistake, not a verdict about a file, so it propagates.

    Args:
        path: The filesystem path to test.

    Returns:
        bool: ``True`` only when the suffix matches and ``_sniff`` accepts the file.

    Examples:
        - The path checks and the suffix are all the base class decides. With the
          default ``_sniff``, which accepts whatever reaches it, an empty file
          under a claimed suffix is recognised and a missing one is not:

            >>> import os
            >>> import tempfile
            >>> from pyramids_mesh._base import BaseDriver
            >>> class TinyDriver(BaseDriver):
            ...     name = "tiny"
            ...     suffixes = (".tiny",)
            >>> driver = TinyDriver()
            >>> with tempfile.TemporaryDirectory() as directory:
            ...     empty = os.path.join(directory, "empty.tiny")
            ...     open(empty, "wb").close()
            ...     verdicts = (
            ...         driver.can_open(empty),
            ...         driver.can_open(os.path.join(directory, "gone.tiny")),
            ...         driver.can_open(directory),
            ...     )
            >>> verdicts
            (True, False, False)

        - A ``_sniff`` that raises never escapes: the file is declined and the
          driver named, so one broken candidate cannot abort dispatch for the rest:

            >>> import os
            >>> import tempfile
            >>> import warnings
            >>> from pyramids_mesh._base import BaseDriver
            >>> class BrokenSniffDriver(BaseDriver):
            ...     name = "broken"
            ...     suffixes = (".tiny",)
            ...
            ...     def _sniff(self, path):
            ...         raise RuntimeError("header parser is wrong")
            >>> with tempfile.TemporaryDirectory() as directory:
            ...     path = os.path.join(directory, "f.tiny")
            ...     with open(path, "wb") as handle:
            ...         _ = handle.write(b"anything at all")
            ...     with warnings.catch_warnings(record=True) as caught:
            ...         warnings.simplefilter("always")
            ...         verdict = BrokenSniffDriver().can_open(path)
            >>> verdict
            False
            >>> str(caught[0].message).split(" and ")[-1]
            'is treated as declining it: RuntimeError: header parser is wrong'
    """
    # Outside the guard on purpose: a bad argument type is the caller's error, not a
    # verdict about a file, so it propagates rather than becoming a warning.
    if not os.path.isfile(path):
        return False
    if not self._has_suffix(path):
        return False
    try:
        return self._sniff(path)
    except Exception as error:  # noqa: BLE001 - the contract is never to raise
        # Narrower than this (OSError alone) left the guarantee false for a _sniff
        # that hit a decoding or parsing error. Declining is the right answer, but
        # a driver whose sniff raises is a bug, so it is named rather than hidden.
        warnings.warn(
            f"{self.name or type(self).__name__} failed to sniff {path!r} and is "
            f"treated as declining it: {type(error).__name__}: {error}",
            stacklevel=2,
        )
        return False

    def mesh_names(self, path: str) -> list[str]:
    """List the topology names in the file.

    A single-mesh format returns a one-item list; ``multi_mesh`` drivers override
    this to read the names from the file.

    Args:

    Returns:
        list[str]: The configured mesh name, as a one-item list.

    read(path, *, mesh_name=None, lazy=True) #

    Read the file into a fully-built pyramids object.

    Template method: _parse turns the file into a :class:ParsedMesh, validate_and_normalise enforces pyramids' invariants, and the result is constructed into a :class:~pyramids.netcdf.ugrid.UgridDataset -- or a :class:~pyramids.netcdf.ugrid.Network1d when the topology is one-dimensional. Do not override it; a driver that bypasses validation loses every invariant.

    Parameters:

    Name Type Description Default
    path str

    The file to read.

    		 required
    mesh_name str | None

    Which topology to build. A format carrying both a surface mesh and a 1D network names them separately -- see mesh_names -- and this selects one. Note that Network1d has no name of its own, so on the 1D path the value only chooses the topology; it is not recorded anywhere.

    		 None
    lazy bool

    Forwarded to _parse so a format with a real deferred loader can honour it.

    		 True

    Returns:

    Type Description
    UgridDataset | Network1d

    UgridDataset | Network1d: The built mesh, or a network for a 1D topology.

    Raises:

    Type Description
    ValueError

    If mesh_name is not one of the topologies mesh_names offers for this file, if the driver offers a 1D topology its _parse did not produce, if a synthesised variable would collide with one the file already defines, or on any invariant :func:~pyramids_mesh._validate.validate_and_normalise enforces.
    Exception

    Whatever _parse raises for a malformed file -- a format driver raises FileFormatNotSupportedError, which is pyramids' own type rather than one invented here.

    Examples:

    • A driver implements _parse and inherits everything else. Here the file is 1-based and its single face is wound clockwise; the template method re-bases the connectivity and reverses the face, so neither mistake can reach the caller:

      import numpy as np from pyramids_mesh._base import BaseDriver, ParsedMesh class TinyDriver(BaseDriver): ... name = "tiny" ... suffixes = (".tiny",) ... capabilities = frozenset({"read_mesh"}) ... ... def _parse(self, path, *, lazy): ... return ParsedMesh( ... node_x=np.array([0.0, 1.0, 1.0]), ... node_y=np.array([0.0, 1.0, 0.0]), ... faces=np.array([[1, 2, 3]]), ... start_index=1, ... ) dataset = TinyDriver().read("anything.tiny") dataset.mesh.n_node, dataset.mesh.n_face (3, 1) dataset.mesh.face_node_connectivity.data.tolist() [[2, 1, 0]]

    • A _parse reporting a one-dimensional topology builds a network instead, which is a separate type with edges rather than faces:

      import numpy as np from pyramids_mesh._base import BaseDriver, ParsedMesh class TinyNetworkDriver(BaseDriver): ... name = "tiny1d" ... suffixes = (".tiny",) ... capabilities = frozenset({"read_mesh"}) ... ... def _parse(self, path, *, lazy): ... return ParsedMesh( ... node_x=np.array([0.0, 1.0, 2.0]), ... node_y=np.array([0.0, 0.0, 0.0]), ... edges=np.array([[0, 1], [1, 2]]), ... topology_dimension=1, ... ) network = TinyNetworkDriver().read("channels.tiny") network.n_node, network.n_edge (3, 2) network.edge_node_connectivity.data.tolist() [[0, 1], [1, 2]]

    • A file holding both a surface and a 1D network puts the latter in network_edges, and mesh_name picks which of the two this read returns. Each read warns about the half it leaves behind:

      import numpy as np import warnings from pyramids_mesh._base import BaseDriver, ParsedMesh class TinyMixedDriver(BaseDriver): ... name = "tinymixed" ... suffixes = (".tiny",) ... capabilities = frozenset({"read_mesh", "multi_mesh"}) ... ... def mesh_names(self, path): ... return ["mesh2d", "network1d"] ... ... def _parse(self, path, *, lazy): ... return ParsedMesh( ... node_x=np.array([0.0, 1.0, 1.0, 2.0]), ... node_y=np.array([0.0, 0.0, 1.0, 1.0]), ... faces=np.array([[0, 1, 2]]), ... network_edges=np.array([[2, 3]]), ... ) driver = TinyMixedDriver() with warnings.catch_warnings(): ... warnings.simplefilter("ignore") ... surface = driver.read("both.tiny") ... channels = driver.read("both.tiny", mesh_name="network1d") surface.mesh.face_node_connectivity.data.tolist() [[0, 1, 2]] channels.edge_node_connectivity.data.tolist() [[2, 3]]

    A multi_mesh driver must name its topologies, because mesh_name is checked against mesh_names: a name the driver does not offer is refused rather than quietly resolved to something else.

    • Asking for the 1D topology of a file that has none is an error rather than an empty network:

      import numpy as np from pyramids_mesh._base import BaseDriver, ParsedMesh class SurfaceOnlyDriver(BaseDriver): ... name = "surfaceonly" ... suffixes = (".tiny",) ... ... def _parse(self, path, *, lazy): ... return ParsedMesh( ... node_x=np.array([0.0, 1.0, 1.0]), ... node_y=np.array([0.0, 0.0, 1.0]), ... faces=np.array([[0, 1, 2]]), ... ) try: ... SurfaceOnlyDriver().read("flat.tiny", mesh_name="network1d") ... except ValueError as error: ... print(str(error).split(";")[0]) surfaceonly does not offer a 'network1d' topology in 'flat.tiny'

    self, path: str, *, mesh_name: str | None = None, lazy: bool = True

        path: The file to read.
        mesh_name: Which topology to build. A format carrying both a surface mesh
            and a 1D network names them separately -- see ``mesh_names`` -- and
            this selects one. Note that ``Network1d`` has no name of its own, so
            on the 1D path the value only chooses the topology; it is not recorded
            anywhere.
        lazy: Forwarded to ``_parse`` so a format with a real deferred loader can
            honour it.

    Returns:
        UgridDataset | Network1d: The built mesh, or a network for a 1D topology.

    Raises:
        ValueError: If ``mesh_name`` is not one of the topologies ``mesh_names``
            offers for this file, if the driver offers a 1D topology its ``_parse``
            did not produce, if a synthesised variable would collide with one the
            file already defines, or on any invariant
            :func:`~pyramids_mesh._validate.validate_and_normalise` enforces.
        Exception: Whatever ``_parse`` raises for a malformed file -- a format
            driver raises ``FileFormatNotSupportedError``, which is pyramids' own
            type rather than one invented here.

    Examples:
        - A driver implements ``_parse`` and inherits everything else. Here the
          file is 1-based and its single face is wound clockwise; the template
          method re-bases the connectivity and reverses the face, so neither
          mistake can reach the caller:

            >>> import numpy as np
            >>> from pyramids_mesh._base import BaseDriver, ParsedMesh
            >>> class TinyDriver(BaseDriver):
            ...     name = "tiny"
            ...     suffixes = (".tiny",)
            ...     capabilities = frozenset({"read_mesh"})
            ...
            ...     def _parse(self, path, *, lazy):
            ...         return ParsedMesh(
            ...             node_x=np.array([0.0, 1.0, 1.0]),
            ...             node_y=np.array([0.0, 1.0, 0.0]),
            ...             faces=np.array([[1, 2, 3]]),
            ...             start_index=1,
            ...         )
            >>> dataset = TinyDriver().read("anything.tiny")
            >>> dataset.mesh.n_node, dataset.mesh.n_face
            (3, 1)
            >>> dataset.mesh.face_node_connectivity.data.tolist()
            [[2, 1, 0]]

        - A ``_parse`` reporting a one-dimensional topology builds a network
          instead, which is a separate type with edges rather than faces:

            >>> import numpy as np
            >>> from pyramids_mesh._base import BaseDriver, ParsedMesh
            >>> class TinyNetworkDriver(BaseDriver):
            ...     name = "tiny1d"
            ...     suffixes = (".tiny",)
            ...     capabilities = frozenset({"read_mesh"})
            ...
            ...     def _parse(self, path, *, lazy):
            ...         return ParsedMesh(
            ...             node_x=np.array([0.0, 1.0, 2.0]),
            ...             node_y=np.array([0.0, 0.0, 0.0]),
            ...             edges=np.array([[0, 1], [1, 2]]),
            ...             topology_dimension=1,
            ...         )
            >>> network = TinyNetworkDriver().read("channels.tiny")
            >>> network.n_node, network.n_edge
            (3, 2)
            >>> network.edge_node_connectivity.data.tolist()
            [[0, 1], [1, 2]]

        - A file holding both a surface and a 1D network puts the latter in
          ``network_edges``, and ``mesh_name`` picks which of the two this read
          returns. Each read warns about the half it leaves behind:

            >>> import numpy as np
            >>> import warnings
            >>> from pyramids_mesh._base import BaseDriver, ParsedMesh
            >>> class TinyMixedDriver(BaseDriver):
            ...     name = "tinymixed"
            ...     suffixes = (".tiny",)
            ...     capabilities = frozenset({"read_mesh", "multi_mesh"})
            ...
            ...     def mesh_names(self, path):
            ...         return ["mesh2d", "network1d"]
            ...
            ...     def _parse(self, path, *, lazy):
            ...         return ParsedMesh(
            ...             node_x=np.array([0.0, 1.0, 1.0, 2.0]),
            ...             node_y=np.array([0.0, 0.0, 1.0, 1.0]),
            ...             faces=np.array([[0, 1, 2]]),
            ...             network_edges=np.array([[2, 3]]),
            ...         )
            >>> driver = TinyMixedDriver()
            >>> with warnings.catch_warnings():
            ...     warnings.simplefilter("ignore")
            ...     surface = driver.read("both.tiny")
            ...     channels = driver.read("both.tiny", mesh_name="network1d")
            >>> surface.mesh.face_node_connectivity.data.tolist()
            [[0, 1, 2]]
            >>> channels.edge_node_connectivity.data.tolist()
            [[2, 3]]

          A ``multi_mesh`` driver must name its topologies, because ``mesh_name``
          is checked against ``mesh_names``: a name the driver does not offer is
          refused rather than quietly resolved to something else.

        - Asking for the 1D topology of a file that has none is an error rather
          than an empty network:

            >>> import numpy as np
            >>> from pyramids_mesh._base import BaseDriver, ParsedMesh
            >>> class SurfaceOnlyDriver(BaseDriver):
            ...     name = "surfaceonly"
            ...     suffixes = (".tiny",)
            ...
            ...     def _parse(self, path, *, lazy):
            ...         return ParsedMesh(
            ...             node_x=np.array([0.0, 1.0, 1.0]),
            ...             node_y=np.array([0.0, 0.0, 1.0]),
            ...             faces=np.array([[0, 1, 2]]),
            ...         )
            >>> try:
            ...     SurfaceOnlyDriver().read("flat.tiny", mesh_name="network1d")
            ... except ValueError as error:
            ...     print(str(error).split(";")[0])
            surfaceonly does not offer a 'network1d' topology in 'flat.tiny'
    """
    parsed = self._parse(path, lazy=lazy)
    parsed = validate_and_normalise(parsed)
    return self._construct(parsed, path=path, mesh_name=mesh_name)
