    XMDF — HDF5 results#

    The XMDF reader. A results-only HDF5 container, read through the vendored GDAL multidimensional API (no declared dependency, no h5py). It carries values and no topology, so it attaches to a mesh you already have.
    Driver name xmdf
    Suffixes .xmdf, .h5
    Capabilities needs_mesh, read_data, lazy_data
    Extra required none
    Returns the variables it read, merged onto the dataset by attach_data 
    from pyramids.netcdf.ugrid import UgridDataset

dataset = UgridDataset.read_file("domain.2dm")
with_results = dataset.attach_data("results.xmdf")

    Structure#

    The file is an HDF5 tree whose root carries a File Type of Xmdf. Each dataset is a group with a Grouptype attribute beginning DATASET, holding Values (n_time, n_element), a Times coordinate, an Active wet/dry mask and precomputed Mins/Maxs. The tree is walked recursively, so the driver is not tied to one container layout.

    Documented limitations#

    • The element-count check is the only thing tying the results to the mesh. A dataset's Values width is matched against the mesh's node or face count to place it; a width matching neither is refused, because nothing in the file identifies its mesh.
    • Summary datasets are skipped, not read as timesteps. A dataset nested under a Final/Maximums container is a single-step snapshot; reading it as a time level would fabricate data.
    • The active mask is a standalone face-located <name>_active variable, never folded into the values as NaN (design §21.2). It is not carried through ParsedVariable.active: the mask counts faces while a dataset may be node-located, so the sibling cannot take the parent's location or shape. It is attached only when its width is the face count.
    • Values are lazy — the loader reopens the file per read and seeks to the array, so it closes over a path, never an open handle; the shape is read from the header.
    • Mins/Maxs are carried as per-timestep minimum/maximum attributes.
    • A layered 3D dataset is refused — a Values array with more than two axes is a 3D result whose ragged vertical levels are not modelled yet (design §21.1).
    • A vector dataset is refused for now; the 2D scalar case ships first.

    class XmdfDriver(BaseDriver):
    """Reader for the XMDF HDF5 results format.

    XMDF carries values and no topology, so the driver declares ``needs_mesh`` and
    implements ``read_data`` rather than ``read``; the values attach to a mesh the caller
    already holds, through ``UgridDataset.read_file("domain.2dm").attach_data("r.xmdf")``.

    The file is an HDF5 tree. Each dataset is a group carrying a ``Grouptype`` attribute
    beginning ``DATASET``, with ``Values`` shaped ``(n_time, n_element)``, a ``Times``
    coordinate, an ``Active`` wet/dry mask and precomputed ``Mins``/``Maxs``. The tree is
    walked recursively, so the driver is not tied to one container layout.

    Documented limitations:
        - **The element-count check is the only thing tying the results to the mesh.** A
          dataset's ``Values`` second axis is matched against the mesh's node or face
          count to place it; a count matching neither is refused, because nothing in the
          file identifies the mesh it belongs to.
        - **Summary datasets are skipped, not read as timesteps.** A dataset nested under
          a ``Final``/``Maximums`` container is a single-step snapshot; reading it as a
          time level would fabricate data, so it is dropped.
        - **The active mask is a standalone face-located variable** ``<name>_active``,
          never folded into the values as NaN (design section 21.2). It is not carried
          through ``ParsedVariable.active``: the mask counts faces while a node-located
          dataset counts nodes, so the sibling cannot take the parent's location or shape.
          It is attached only when its width matches the mesh's face count.
        - **Values are lazy.** The loader reopens the file per read and seeks to the
          dataset's array, so it closes over a path, never an open handle (design section
          7); the shape is read from the header without loading the values.
        - ``Mins``/``Maxs`` are carried as per-timestep ``minimum``/``maximum`` attributes.
        - **A layered 3D dataset is refused.** A ``Values`` array with more than two axes
          is a 3D result whose ragged vertical levels this package does not model yet
          (design section 21.1); it is refused rather than flattened.
        - A vector dataset (``Grouptype`` containing ``VECTOR``) is refused for now --
          the 2D scalar case ships first.

    Example:
        Attach an XMDF results file to the mesh it belongs to. The example is shown
        rather than executed as a doctest because XMDF needs a real HDF5 file, which
        cannot be built inline::

            from pyramids.netcdf.ugrid import UgridDataset

            dataset = UgridDataset.read_file("domain.2dm")
            attached = dataset.attach_data("results.xmdf")
            depth = attached.get("Minimum dt")       # node-located, (n_time, n_node)
            depth.attributes["time_values"]           # the Times coordinate
            attached.get("Minimum dt_active")         # per-face wet/dry mask sibling
    """

    name = "xmdf"
    long_name = "XMDF HDF5 results"
    suffixes = (".xmdf", ".h5")
    api_version = MESH_DRIVER_API_VERSION
    capabilities = frozenset({"needs_mesh", "read_data", "lazy_data"})

    def _sniff(self, path: str) -> bool:
        """Report whether the file is XMDF: HDF5 magic plus a ``File Type`` of ``Xmdf``.

        The magic is checked first and cheaply; only then is the file opened to read the
        root ``File Type`` array, so a non-HDF5 file never reaches GDAL. ``.h5`` is a
        generic HDF5 suffix shared with other formats, which is why the ``File Type``
        value -- not just the suffix -- decides.

        Args:
            path: The file to inspect.

        Returns:
            bool: ``True`` when the magic matches and ``File Type`` reads ``Xmdf``.
        """
        with open(path, "rb") as handle:
            if handle.read(len(_HDF5_MAGIC)) != _HDF5_MAGIC:
                return False
        with gdal.ExceptionMgr(useExceptions=True):
            try:
                dataset = gdal.OpenEx(path, gdal.OF_MULTIDIM_RASTER | gdal.OF_READONLY)
            except RuntimeError:
                return False
            try:
                root = dataset.GetRootGroup()
                if _FILE_TYPE not in root.GetMDArrayNames():
                    return False
                value = root.OpenMDArray(_FILE_TYPE).Read()
            finally:
                dataset.Close()
        return bool(value) and str(value[0]) == _FILE_TYPE_VALUE

    def read(
        self, path: str, *, mesh_name: str | None = None, lazy: bool = True
    ) -> UgridDataset:
        """Refuse the mesh-reading entry point, naming the one to use instead.

        Args:
            path: The results file, named in the message.
            mesh_name: Unused.
            lazy: Unused.

        Returns:
            UgridDataset: Never -- the signature matches the driver protocol so the
                refusal is a clear message rather than a ``TypeError``.

        Raises:
            ValueError: Always. XMDF carries values and no topology.
        """
        raise ValueError(
            f"{self.name} carries values but no mesh, so it has no read(); attach it to "
            f"a mesh you already have with "
            f"UgridDataset.read_file(mesh_path).attach_data({path!r})"
        )

    def read_data(
        self, path: str, dataset: UgridDataset, *, lazy: bool = True
    ) -> dict[str, MeshVariable]:
        """Read an XMDF file's datasets as variables for a mesh the caller supplies.

        Args:
            path: The XMDF file to read.
            dataset: The mesh the values attach to, for the element-count check.
            lazy: When ``True``, leave each dataset's values behind a loader.

        Returns:
            dict[str, MeshVariable]: One variable per dataset, plus a face-located
                ``<name>_active`` sibling for each dataset carrying an active mask.

        Raises:
            FileFormatNotSupportedError: If a dataset is 3D or vector, or no dataset's
                element count matches the mesh.
            ValueError: If a dataset's element count matches neither the node nor the
                face count of ``dataset``.
        """
        n_node = int(dataset.mesh.n_node)
        n_face = int(dataset.mesh.n_face)
        reader = _XmdfReader(path, n_node=n_node, n_face=n_face, lazy=lazy)
        parsed = reader.read()
        return self._build_data_variables(parsed, dataset.mesh_name)

    can_open(path) #

    Report whether this driver recognises the file, without ever raising.

    A missing path or a directory answers False, and so does a suffix this driver does not claim. Everything about the file's content is the subclass's _sniff to judge, and the default _sniff judges nothing -- so on BaseDriver itself an empty file with a claimed suffix answers True. A driver that means to decline an empty or foreign file reads a header signature, as :meth:~pyramids_mesh.drivers.sms.TwoDmDriver._sniff does.

    A _sniff that fails for any reason is reported as a warning and the file declined, so a broken candidate cannot abort driver dispatch. Only _sniff sits inside that guard: a TypeError from being handed something that is not a path is the caller's mistake, not a verdict about a file, so it propagates.

    Parameters:

    Name Type Description Default
    path str

    The filesystem path to test.

    		 required

    Returns:

    Name Type Description
    bool bool

    True only when the suffix matches and _sniff accepts the file.

    Examples:

    • The path checks and the suffix are all the base class decides. With the default _sniff, which accepts whatever reaches it, an empty file under a claimed suffix is recognised and a missing one is not:

      import os import tempfile from pyramids_mesh._base import BaseDriver class TinyDriver(BaseDriver): ... name = "tiny" ... suffixes = (".tiny",) driver = TinyDriver() with tempfile.TemporaryDirectory() as directory: ... empty = os.path.join(directory, "empty.tiny") ... open(empty, "wb").close() ... verdicts = ( ... driver.can_open(empty), ... driver.can_open(os.path.join(directory, "gone.tiny")), ... driver.can_open(directory), ... ) verdicts (True, False, False)

    • A _sniff that raises never escapes: the file is declined and the driver named, so one broken candidate cannot abort dispatch for the rest:

    def can_open(self, path: str) -> bool:
    """Report whether this driver recognises the file, without ever raising.

    A missing path or a directory answers ``False``, and so does a suffix this
    driver does not claim. Everything about the file's *content* is the subclass's
    ``_sniff`` to judge, and the default ``_sniff`` judges nothing -- so on
    ``BaseDriver`` itself an empty file with a claimed suffix answers ``True``. A
    driver that means to decline an empty or foreign file reads a header signature,
    as :meth:`~pyramids_mesh.drivers.sms.TwoDmDriver._sniff` does.

    A ``_sniff`` that fails for any reason is reported as a warning and the file
    declined, so a broken candidate cannot abort driver dispatch. Only ``_sniff``
    sits inside that guard: a ``TypeError`` from being handed something that is not
    a path is the caller's mistake, not a verdict about a file, so it propagates.

    Args:
        path: The filesystem path to test.

    Returns:
        bool: ``True`` only when the suffix matches and ``_sniff`` accepts the file.

    Examples:
        - The path checks and the suffix are all the base class decides. With the
          default ``_sniff``, which accepts whatever reaches it, an empty file
          under a claimed suffix is recognised and a missing one is not:

            >>> import os
            >>> import tempfile
            >>> from pyramids_mesh._base import BaseDriver
            >>> class TinyDriver(BaseDriver):
            ...     name = "tiny"
            ...     suffixes = (".tiny",)
            >>> driver = TinyDriver()
            >>> with tempfile.TemporaryDirectory() as directory:
            ...     empty = os.path.join(directory, "empty.tiny")
            ...     open(empty, "wb").close()
            ...     verdicts = (
            ...         driver.can_open(empty),
            ...         driver.can_open(os.path.join(directory, "gone.tiny")),
            ...         driver.can_open(directory),
            ...     )
            >>> verdicts
            (True, False, False)

        - A ``_sniff`` that raises never escapes: the file is declined and the
          driver named, so one broken candidate cannot abort dispatch for the rest:

            >>> import os
            >>> import tempfile
            >>> import warnings
            >>> from pyramids_mesh._base import BaseDriver
            >>> class BrokenSniffDriver(BaseDriver):
            ...     name = "broken"
            ...     suffixes = (".tiny",)
            ...
            ...     def _sniff(self, path):
            ...         raise RuntimeError("header parser is wrong")
            >>> with tempfile.TemporaryDirectory() as directory:
            ...     path = os.path.join(directory, "f.tiny")
            ...     with open(path, "wb") as handle:
            ...         _ = handle.write(b"anything at all")
            ...     with warnings.catch_warnings(record=True) as caught:
            ...         warnings.simplefilter("always")
            ...         verdict = BrokenSniffDriver().can_open(path)
            >>> verdict
            False
            >>> str(caught[0].message).split(" and ")[-1]
            'is treated as declining it: RuntimeError: header parser is wrong'
    """
    # Outside the guard on purpose: a bad argument type is the caller's error, not a
    # verdict about a file, so it propagates rather than becoming a warning.
    if not os.path.isfile(path):
        return False
    if not self._has_suffix(path):
        return False
    try:
        return self._sniff(path)
    except Exception as error:  # noqa: BLE001 - the contract is never to raise
        # Narrower than this (OSError alone) left the guarantee false for a _sniff
        # that hit a decoding or parsing error. Declining is the right answer, but
        # a driver whose sniff raises is a bug, so it is named rather than hidden.
        warnings.warn(
            f"{self.name or type(self).__name__} failed to sniff {path!r} and is "
            f"treated as declining it: {type(error).__name__}: {error}",
            stacklevel=2,
        )
        return False
